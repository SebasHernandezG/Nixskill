# Desktop A/B pilot: revenue, 2026-11-21

This is a single synthetic case with two matched pairs, run on Codex Desktop after the CLI benchmark could not execute commands in this environment. The order was baseline → Nixskill → Nixskill → baseline. Each chat used the same prompt from `evals/cases.json`, `gpt-6.1-sol`, medium reasoning effort, and the same local permission mode. Only the candidate workspaces contained `.agents/skills/nixskill`. Both candidate task logs show a successful read of `SKILL.md`; neither baseline log shows one.

Task token counts below come from the local Codex JSONL `token_usage_record` for each first turn. The separate telemetry flush turns are excluded. Cached input is already included in input, and reasoning output is already included in output. The Langfuse smoke trace and all four task traces were verified in the Nixskill project. Langfuse's usage breakdown matched each local input, cached input, output, and total exactly. The two candidate root traces show `skill:nixskill`; neither baseline root trace does.

The shared refund check was **discovered after pair 1** and kept separate at `evals/posthoc/revenue-shared-refund.mjs` while the original pilot ran. It presents the *same refund object* in two eligible orders. Counting that record once yields 1,900 cents. Baseline 1, Nixskill 2, and baseline 2 yield 1,800 cents. This avoids assuming whether IDs are global or order-local: object identity alone establishes that the record is shared. All four workspaces still pass their own visible tests and the original hidden check, and preserve the seven public exports.

The observed token increase is descriptive, not a quality-equivalent estimate of Nixskill's effect. The first pair differs in correctness under the additional check; the second pair has two incomplete solutions. It provides **no evidence of token savings**. A read-only review of pair 1 found seven model generations and six command-tool calls with Nixskill versus five and four without it. Both arms read the same nine relevant code and test files once. The candidate also read `SKILL.md`, split related reads into two rounds, ran a pre-edit test, and inspected its diff after the edit. Those extra rounds explain much of the larger input count. The data do not establish that any one step was unnecessary for other tasks.

The original run was prepared at repository revision `b8f47d2`; `manifest.json`, `verification.json`, and per-pair observations are in the local run directory `%LOCALAPPDATA%\Nixskill\manual-runs\manual-UrAnwc`. A Windows line-ending conversion changed raw source bytes without changing Git content, so the verifier was updated to accept LF/CRLF-only differences. After this pilot, the shared refund assertion was added to the revenue hidden check for **future** runs. That changes the case hash: the existing pilot must be interpreted using its frozen original check plus the labeled post hoc check, rather than rerun against the new check as if it were pre-registered.

## Next experiment

1. Clarify the identity and scope of a refund record in the case prompt and hidden check before preparing new workspaces.
2. Test a small skill revision that groups related reads and makes extra test or review rounds answer a concrete uncertainty; preserve verification after editing.
3. Run balanced pairs on more than one programming case. Compare token use only for pairs that pass the same complete quality gate and have observed skill activation. Report failures and missing telemetry.

This pilot measures task tokens, not actual subscription billing. Langfuse cost estimates may price cached and uncached input differently.
